# WorkReport HR-Pro 产品需求说明书（PRD）

> 版本：V1.0 ｜ 用途：提交人力资源专家团辅助验证、评估与完善需求

---

## 一、产品概述

### 1.1 背景与痛点

传统工作汇报（以周报为例）存在以下问题：

| # | 痛点 | 详细描述 |
|---|------|---------|
| 1 | 催办低效 + 信息不标准化 | 管理者需人工提醒、反复催办；即便催完，每个人表达方式、话术不同、填写完整性不一，管理者统一整理需逐一沟通确认"这是什么事、做到什么程度、目标是什么" |
| 2 | 工作断档 | 一周一个表，回溯过去工作需翻旧文档才能回忆 |
| 3 | 随时随地汇报难 | 不只季/半年/年度要汇报，领导随时可能要求汇报，需准确、及时的信息与数据 |
| 4 | 做 PPT 费时费力 | 半年度、年度做 PPT 汇报需专门花时间整理 |
| 5 | 临时工作打乱主线 | 临时交办工作让精力分散、脱离年度目标主线；临时工作需记录，但要做分层，判断哪些围绕核心重点目标、哪些是辅助性 |

### 1.2 产品定位

一个**工作汇报工具**（不是看板系统）。它是「团队人力工具大中台」的一个组成模块，与平台内其他工具（如独立的看板工具）协同。

以「工作事项卡片」为最小颗粒度的持续记录与自动聚合系统。将"周期性空对空写报告"转变为"持续的结构化工作日志 + 自动聚合输出"。

**实际应用场景**：
- 团队内部周例会
- 周报记录
- 应对领导不定期的工作简要汇报/呈现

### 1.3 核心价值主张（灵魂能力）

**智能累计**：系统是一个"懂 HR 的数据专家"，能识别工作的性质（累计制 vs 一次性），自动累计数据，输出"本周 X + 2026年累计 XX"的结构化呈现。员工只需填报当周数据，系统自动完成累计与洞察。

## 三、核心概念

### 3.1 工作事项

系统最小颗粒度。一个工作事项有生命周期（可能持续数周甚至全年），每周更新进展。

**字段：**

| 字段 | 说明 |
|------|------|
| 事项名称 | 这件工作是什么 |
| 分类 | 年度重点工作 / 自主专项工作 / 常规工作 |
| 重要性标签 | 高 / 中 / 低（叠加在分类上，判断核心 vs 辅助） |
| 所属年度目标 | 挂载到 6 项年度目标之一（可选） |
| 负责人 | 归属成员 |
| 预计完成时间 | 用于判断进度正常/临期/延期 |
| 附件 | 明细数据（招聘明细表、项目推进表等），员工周报时自主上传 |

### 3.2 工作状态（5 种）

| 状态 | 颜色 | 含义 |
|------|------|------|
| 已完成 | 绿 | 工作完成，计入累计成果 |
| 进行中 | 蓝 | 正常推进中 |
| 临期 | 黄 | 临近预计完成时间 |
| 延期 | 橙 | 已过预计完成时间或明显落后 |
| 暂停/终止 | 红 | 因特殊原因暂停或终止 |

已完成的工作也需呈现，体现累计成果。

### 3.3 年度目标

以年度目标为顶层锚点，6 项目标含权重：

| # | 目标 | 权重 |
|---|------|------|
| 1 | 聚焦经营战略推动组织和人才规划布局 | 20% |
| 2 | 严控人力预算成本+季度人效分析+合规零风险 | 20% |
| 3 | 深入业务一线，推动组织/人才/激励专项方案 | 30% |
| 4 | 高效协同 COE 完成人力资源政策 100% 落地 | 15% |
| 5 | 夯实基础设施建设+AI 提效探索 | 5% |
| 6 | 加强 COE 与 HRBP 协同+团队绩优骨干保留 | 10% |

### 3.4 汇报粒度

以「周」为单位。信息标准化方式：不强制套模板，由 AI 审阅 Agent 对话式补充统一。

## 四、功能需求

### 4.1 工作事项管理

- 成员可增删改自己的工作事项
- 事项归属三类分类 + 重要性标签 + 年度目标 + 预计完成时间
- 支持附件（明细数据）

### 4.2 周报填写

- 每周填写：本周进展、下阶段计划、所需支持/待决策事项
- 员工填写后由审阅 Agent 对话式补充完善
- 支持保存草稿

### 4.3 附件上传

- 周报填写时，员工自主决定是否上传附件（明细数据）
- 附件类型：招聘进度明细表、重点项目推进表、外包管理表等
- 上传的明细数据持续积累 → 生成汇报视图
- 数据来源分两阶段：1.0 人工录入+上传报表 / 2.0 AI 自动取数（对接招聘系统）

### 4.4 管理者汇报视图

一个实时更新的汇报视图，与季/半年/年度报告共用同一套格式模板（汇报视图=实时活数据，报告=定格快照）。

**三个使用场景：**

| 场景 | 颗粒度 | 关注点 |
|------|--------|--------|
| 团队周例会 | 最细（每项工作） | 逐项过工作进展 |
| 干部周例会 | 中等 | 重点事项 + 待决策 |
| 大老板汇报 | 最粗 | 重点数据 + 重点项目 + 待决策 |

**汇报视图结构（结论→重点→细节→行动）：**
1. AI 一句话总结
2. 关键数据（图文并茂）
3. 重点工作项目进度（进度条 + 状态 + 附件）
4. 日常工作明细（按人/板块分组，默认收起）
5. 待办事宜 + 需决策事项

### 4.5 报告生成

- 月报/季报：每月/季第一个周一自动生成
- 年报：手动触发，指定时间范围
- 输出：Web 在线查看 + HTML + PDF

### 4.6 智能累计（信息提炼）

- 识别累计制工作（招聘交付人数、员工访谈人数、培训场次、组织/人员调动等）
- 自动累计历史数据，输出"本周 X + 2026年累计 XX"

### 4.7 Agent 进化与反馈机制

系统通过「反馈闭环」让 Agent 持续进化，越来越懂团队的 HR 工作：

```
Agent 工作 → 管理者审核 → 纠正/认可 → 沉淀为经验规则 → 注入知识库 → 下次更准
```

- **纠错/认可按钮**：Agent 每次判断、追问、累计，旁边有「👍 认可 / 👎 纠正」入口
- **经验规则库**：每条纠正沉淀为一条规则（如"校招签约数也是累计制"）
- **规则注入**：规则不断并入 Agent 知识库，下次自动参考
- **定期进化**：每积累一批（或管理者手动触发），把规则整理进提示词，系统化升级

**价值**：把 HR 总监的专业经验持续"教"给 AI，系统越用越专业。

### 4.8 上周待办回溯

每周周会时，系统自动回溯上周待办的完成情况，形成「上周待办 → 本周完成状态」的对照，便于周会逐项确认。

## 五、Agent 架构（6 个智能体）

| Agent | 触发时机 | 核心能力 |
|-------|---------|---------|
| 审阅 Agent | 员工草拟周报后 | 判断进展、精简内容、追问补全（如"访谈了哪几个团队的谁"）、标准化表达；对话式不退回 |
| 催办 Agent | 每周五 | 定时提醒、催办、群内@人 |
| 待办 Agent | 周例会后 | 综合周报+批注+会议纪要，提取下阶段待办 |
| 信息提炼 Agent | 审阅完成后 | 识别工作性质、累计制自动累计、提炼结构化数据 |
| 报告 Agent | 月/季/年 | 时间维度+目标维度聚合 |
| 解读 Agent | 报告完成后 | 调用 HR 专家知识库，专业洞察分析 |

**协作关系**：审阅 Agent 追问补全信息 → 信息提炼 Agent 在信息补全后累计提炼 → 报告 Agent 聚合 → 解读 Agent 洞察。

### 催办时间线

| 时间 | 动作 |
|------|------|
| 周五 16:00 | 群内全员提醒，管理者收到提交状态 |
| 周五 18:00 / 21:00 | 群内@未完成成员催办 |
| 周五 24:00 - 周六 10:00 | 静默时段 |
| 周六 10:00 | 群内提示"因XXX未完成，周报未能按时生成" |
| 此后每 3 小时 | 持续催办（0:00-10:00 静默） |
| 全员提交后 | 自动生成周报推送管理者 |

## 八、技术栈

- 后端：Python FastAPI + SQLite
- 前端：原生 HTML/CSS/JS 单页应用（含移动端适配）
- AI 引擎：DeepSeek V4-Pro / V4-Flash API（HR 专业能力靠提示词 + 知识库注入，非训练模型）
- 账号登录：需要（登录方式待定：企业微信扫码 / 账号密码）
- 部署：公司 Linux 服务器（systemd + Nginx）

## 九、待明确事项（开放问题）

以下为尚未完全明确的需求点，供专家团评估时重点关注：

1. **登录方式**：企业微信扫码 还是 账号密码？（已确认需要登录，方式未定）
2. **数据上云政策**：已按方案 A 推进（接受 HR 数据经 DeepSeek API 上云），公司数据安全政策后续复核，如有限制再调整
3. **审阅对话载体**：员工与审阅 Agent 的对话在 Web 端还是企业微信内？
4. **临时工作来源**：临时交办工作由员工自建还是管理者指派？
5. **成员管理**：团队成员新增/离职如何维护？是否对接企业微信通讯录？
6. **重要性标签确定方式**：由员工自标、管理者定、还是 AI 自动判断？
7. **敏感数据隔离**：工作记录全员可见，涉及薪酬等敏感内容如何处理？

## 十、已确认的补充决策

| 决策项 | 结论 |
|--------|------|
| 账号登录 | 需要登录系统 |
| AI 引擎 | 方案 A：DeepSeek V4-Pro / Flash 云端 API（提示词+知识库注入 HR 能力，非训练模型） |
| 历史数据迁移 | 迁"骨架"（目标/事项/负责人），不迁历史周报明细，旧文件归档 |
| 移动端 | 最好支持移动端查看汇报视图 |
| 待办回溯 | 每周周会回溯上周待办完成情况 |
| 工作状态标记 | 已完成 / 暂停由员工自行标记 |
| 智能累计边界 | 交专家团进一步判断 |
