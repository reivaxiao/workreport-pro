# 工作汇报系统产品原型说明文档

## 一、产品背景与目标

### 1.1 痛点分析

传统的工作汇报（以周报为例）存在以下问题：

| 问题 | 描述 |
|------|------|
| 催办低效 | 管理者需人工提醒、催办，效率低下 |
| 格式不统一 | 成员填写内容格式各异，内容不完整 |
| 工作断档 | 周报独立分散，回溯历史需翻阅多个文档 |
| 汇总困难 | 半年度/年度总结需翻阅大量周报，信息碎片化 |
| PPT 耗时 | 做汇报 PPT 需专门花时间整理 |
| 精力分散 | 临时交办工作脱离年度目标主线，难以评估工作量产出 |

### 1.2 产品定位

一个以「工作事项卡片」为最小颗粒度的持续记录与自动聚合系统。核心理念是将"周期性空对空写报告"转变为"持续的结构化工作日志 + 自动聚合输出"。

### 1.3 产品名称（待定）

暂定：WorkReport Pro

## 二、团队结构

```
肖凌华（管理者：集团招聘总监兼 KA-HRBP 总监）
├── 程宇欣：招聘 COE + HRIS
├── 李微微：HRBP → KA 营销板块
├── 高丽茹：HRBP → KA 产研板块
└── 李　雯：HRBP → KA 运营板块
```

COE 负责体系搭建、流程建设、工具开发（产出偏平台和规则）；HRBP 负责业务交付、人效监控、人才梯队（产出偏服务和结果）。三个 HRBP 服务不同板块，同类工作并行但独立。

## 三、核心功能设计

### 3.1 工作事项分类

| 分类 | 定义 | 来源 |
|------|------|------|
| **年度重点工作** | 从部门年度目标/OKR 直接拆解 | 自上而下 |
| **自主专项工作** | 团队自驱发起的重要项目或改进事项 | 自下而上 |
| **常规工作** | 支撑型、周期性事务 | 常态化 |

### 3.2 年度目标体系

以年度目标作为顶层锚点，6 项目标含权重（详见肖凌华 2026 年度目标书）：

| # | 目标 | 权重 | 类别 |
|---|------|------|------|
| 1 | 聚焦经营战略推动组织和人才规划布局 | 20% | 业务 |
| 2 | 严控人力预算成本+季度人效分析+合规零风险 | 20% | 业务 |
| 3 | 深入业务一线，推动组织/人才/激励专项方案 | 30% | 业务 |
| 4 | 高效协同 COE 完成人力资源政策 100% 落地 | 15% | 业务 |
| 5 | 夯实基础设施建设+AI 提效探索 | 5% | 业务 |
| 6 | 加强 COE 与 HRBP 协同+团队绩优骨干保留 | 10% | 管理 |

每条工作事项可挂载到具体年度目标下，年底自动汇总目标达成情况。

### 3.3 汇报粒度

以「周」为单位。每个工作事项有生命周期（可能持续数周甚至全年），每周更新进展。报告按分类自动区分展示层级：

- **年度重点工作**：报告中也突出展示
- **常规工作/自主专项**：报告中简略呈现（仅标题），但保留作为工作量参考

## 四、Agent 架构

系统包含五个独立运行的智能体：

### 4.1 审阅 Agent
- **触发时机**：员工草拟周报后
- **核心能力**：
  - 结合历史周报判断工作进展和推进阶段
  - 精简提炼员工输入的内容
  - 对描述不清晰的部分主动追问（如"具体成果是什么？""是否有量化数据？"）
  - 给予工作推进进度的建议
- **交互方式**：纯对话式，不采用退回机制。员工自行决定是否采纳建议
- **权限**：AI 审阅对话记录仅管理者可见

### 4.2 催办 Agent
- **触发时机**：每周五
- **时间线**：

| 时间 | 动作 |
|------|------|
| 周五 16:00 | 群内 @all 全员提醒，管理者收到提交状态 |
| 周五 18:00 | 群内 @未完成成员 催办 |
| 周五 21:00 | 群内 @未完成成员 催办 |
| 周五 24:00 - 周六 10:00 | 静默时段，不推送任何信息 |
| 周六 10:00 | 群内提示 "因XXX未完成，本周周报未能按时生成" |
| 此后每 3 小时 | 群内 @未完成成员 持续催办（0:00-10:00 静默） |
| 全员提交后 | 自动生成周报推送管理者 |

### 4.3 待办 Agent
- **触发时机**：周例会结束后
- **输入来源**：
  - 全体成员周报内容
  - 管理者批注（周会共识）
  - 上传的腾讯会议纪要
- **输出**：下阶段工作待办事项清单

### 4.4 报告 Agent
- **核心能力**：
  - 时间维度聚合（周→月→季→年）
  - 年度目标维度聚合（每个目标下所有关联工作的进展轨迹）
- **触发机制**：
  - 月报：每月第一个周一自动生成
  - 季报：每季度第一个周一自动生成
  - 年报：手动触发，需指定时间范围
- **输出格式**：Web 端在线查看 + HTML + PDF
- **展示规则**：按分类自动区分，年度重点工作突出展示

### 4.5 解读 Agent
- **触发时机**：报告 Agent 完成后自动触发
- **核心能力**：
  - 调用 HR 专家知识库（如 WorkBuddy 人力资源专家团）
  - 从专业视角对报告进行洞察与分析
  - 输出解读分析报告
- **后续流程**：解读完成后进入「团队综合审阅→修改优化→正式版发布」

## 五、管理者操作

管理者不进行传统的"审批通过/打回重写"，而是：

- 在团队周例会讨论后，在各成员工作事项旁**逐条批注**（记录周会达成的共识、下阶段方向）
- 批注仅管理者与被批注成员可见
- 批注作为待办 Agent 的输入源之一

## 六、权限模型

| 数据 | 可见范围 |
|------|----------|
| 工作记录 | 全员可见 |
| AI 审阅对话记录 | 仅管理者可见 |
| 管理者批注 | 仅管理者与被批注人可见 |
