# 工作汇报系统产品原型说明文档

## 一、产品背景与目标

### 1.1 痛点分析

传统的工作汇报（以周报为例）存在以下问题：

| # | 问题 | 详细描述 |
|---|------|---------|
| 1 | 催办低效 + 信息不标准化 | 管理者需人工提醒、反复催办；即便催完，每个人表达方式、话术不同，填写完整性不一，管理者要统一整理就得逐一沟通确认"这是什么事、做到什么程度、目标是什么" |
| 2 | 工作断档 | 一周一个表，回溯过去工作需翻旧文档才能回忆 |
| 3 | 随时随地汇报难 | 不只季度/半年度/年度要汇报，领导随时可能要求汇报，需要准确、及时的信息和数据 |
| 4 | 做 PPT 费时费力 | 半年度、年度做 PPT 汇报需专门花时间整理 |
| 5 | 临时工作打乱主线 | 临时交办工作让精力分散、脱离年度目标主线；临时工作需记录，但要做分层，判断哪些围绕核心重点目标、哪些是辅助性 |

### 1.2 产品定位

一个以「工作事项卡片」为最小颗粒度的持续记录与自动聚合系统。核心理念是将"周期性空对空写报告"转变为"持续的结构化工作日志 + 自动聚合输出"。

### 1.3 产品名称

WorkReport HR-Pro

## 三、核心功能设计

### 3.1 工作事项分层

工作事项有**两个维度**的划分：

**维度一：分类（固定三类）**

| 分类 | 定义 | 来源 |
|------|------|------|
| **年度重点工作** | 从部门年度目标/OKR 直接拆解 | 自上而下 |
| **自主专项工作** | 团队自驱发起的重要项目或改进事项 | 自下而上 |
| **常规工作** | 支撑型、周期性事务 | 常态化 |

**维度二：重要性标签（高/中/低）**

叠加在分类之上，用来更直观地判断哪些是围绕核心重点目标开展的工作、哪些是辅助性工作。

### 3.2 年度目标体系

以年度目标作为顶层锚点，6 项目标含权重（详见肖凌华 2026 年度目标书）：

| # | 目标 | 权重 | 类别 |
|---|------|------|------|
| 1 | 聚焦经营战略推动组织和人才规划布局 | 20% | 业务 |
| 2 | 严控人力预算成本+季度人效分析+合规零风险 | 20% | 业务 |
| 3 | 深入业务一线，推动组织/人才/激励专项方案 | 30% | 业务 |
| 4 | 高效协同 COE 完成人力资源政策 100% 落地 | 15% | 业务 |
| 5 | 夯实基础设施建设+AI 提效探索 | 5% | 业务 |
| 6 | 加强 COE 与 HRBP 协同+团队绩优骨干保留 | 10% | 管理 |

每条工作事项可挂载到具体年度目标下。

### 3.3 汇报粒度与信息标准化

以「周」为单位。每个工作事项有生命周期（可能持续数周甚至全年），每周更新进展。

**信息标准化方式**：不强制套模板，保持自由填写，由 AI 审阅 Agent 在对话中帮助统一和补充（追问"是什么事、做到什么程度、目标是什么、有无量化数据"）。

报告按分类 + 重要性标签自动区分展示层级：年度重点工作 / 高重要性事项突出展示，常规工作 / 低重要性事项简略呈现（仅标题），但保留作为工作量参考。

## 四、Agent 架构

系统包含六个独立运行的智能体：

### 4.1 审阅 Agent
- **触发时机**：员工草拟周报后
- **核心能力**：
  - 结合历史周报判断工作进展和推进阶段
  - 精简提炼员工输入的内容
  - 对描述不清晰、信息不完整的部分主动追问（"具体成果是什么？""是否有量化数据？""访谈了哪几个团队的谁？"）
  - 帮助标准化表达（统一"是什么事、做到什么程度、目标是什么"）
- **交互方式**：纯对话式，不采用退回机制，员工自行决定是否采纳
- **权限**：AI 审阅对话记录仅管理者可见

### 4.2 催办 Agent
- **触发时机**：每周五
- **时间线**：

| 时间 | 动作 |
|------|------|
| 周五 16:00 | 群内 @all 全员提醒，管理者收到提交状态 |
| 周五 18:00 | 群内 @未完成成员 催办 |
| 周五 21:00 | 群内 @未完成成员 催办 |
| 周五 24:00 - 周六 10:00 | 静默时段，不推送 |
| 周六 10:00 | 群内提示 "因XXX未完成，本周周报未能按时生成" |
| 此后每 3 小时 | 群内 @未完成成员 持续催办（0:00-10:00 静默） |
| 全员提交后 | 自动生成周报推送管理者 |

### 4.3 待办 Agent
- **触发时机**：周例会结束后
- **输入来源**：全体成员周报 + 管理者批注（周会共识）+ 上传的腾讯会议纪要
- **输出**：下阶段工作待办事项清单

### 4.4 信息提炼 Agent
- **触发时机**：员工周报审阅完成后自动触发
- **核心能力**：
  - 识别工作性质：判断是「累计制」（如招聘交付人数、员工访谈人数、累计培训场次、累计组织/人员调动）还是「一次性项目」
  - 对累计制工作自动累计历史数据，输出「本周 X + 2026年累计 XX」的结构化呈现
  - 提炼结构化数据，供看板和报告直接使用
- **核心价值**：系统的灵魂能力——不只是记录本，而是懂 HR 的数据专家，自动识别、自动累计、自动洞察
- **与审阅 Agent 的协作**：审阅 Agent 负责追问补全信息（如"访谈了谁"），信息提炼 Agent 在信息补全后做累计提炼

### 4.5 报告 Agent
- **核心能力**：时间维度聚合（周→月→季→年）+ 年度目标维度聚合
- **触发机制**：月报/季报每月/季第一个周一自动生成；年报手动触发（指定时间范围）
- **输出格式**：Web 端在线查看 + HTML + PDF

### 4.6 解读 Agent
- **触发时机**：报告 Agent 完成后自动触发
- **核心能力**：调用 HR 专家知识库（如 WorkBuddy 人力资源专家团），从专业视角洞察分析
- **后续流程**：解读完成后进入「团队综合审阅 → 修改优化 → 正式版发布」

## 五、管理者专属看板

### 5.1 定位

一个**实时更新的汇报看板**，用于回答领导"随时随地"的汇报需求。

### 5.2 核心设计

看板与季度/半年度/年度报告的**格式模板完全一致**，区别在于：

| | 管理者看板 | 季度/半年/年度报告 |
|---|---|---|
| 数据状态 | 实时刷新 | 某个时间点的快照 |
| 用途 | 随时回答领导提问 | 正式汇报材料 |
| 触发 | 打开即看 | 定时/手动生成 |

即：系统有一套统一的"汇报模板"，看板是"活的数据"，正式报告是"定格的快照"。

### 5.3 看板能力

- 实时显示所有成员本周工作进展、关键数据、完成情况
- 支持按年度目标、业务板块、工作分类等维度快速筛选
- 打开即可用来回答领导提问

## 六、管理者操作

管理者不进行传统的"审批通过/打回重写"，而是：

- 在团队周例会讨论后，在各成员工作事项旁**逐条批注**（记录周会共识、下阶段方向）
- 批注仅管理者与被批注成员可见
- 批注作为待办 Agent 的输入源之一

| 管理者批注 | 仅管理者与被批注人可见 |
