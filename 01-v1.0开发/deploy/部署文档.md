# WorkReport HR-Pro 部署文档

本文档面向运维/服务器管理员，说明如何把系统部署到公司 Linux 服务器。

## 一、系统概况

| 项目 | 说明 |
|------|------|
| 名称 | WorkReport HR-Pro 智能工作汇报系统 |
| 后端 | Python FastAPI |
| 前端 | 原生 HTML/CSS/JS 单页应用（由后端托管） |
| 数据库 | SQLite（单文件 `workreport.db`） |
| 附件存储 | 本地目录 `src/uploads/` |
| AI 接口 | 公司网关 `https://atk.llschain.com/v1`（DeepSeek） |
| 端口 | 后端监听 8899，Nginx 反代到 80/443 |

## 二、目录规划（以 /opt/workreport 为例）

```
/opt/workreport/
├── src/
│   ├── backend/          # 后端代码（main.py、routers、models、config.py）
│   ├── frontend/         # 前端（index.html、字体）
│   ├── uploads/          # 附件上传目录
│   └── workreport.db     # SQLite 数据库文件
├── backups/              # 数据库备份目录（由 backup.py 生成）
├── venv/                 # Python 虚拟环境
└── ...
```

## 三、部署步骤

### 1. 上传代码
把项目 `src/` 目录整个上传到服务器，例如解压到 `/opt/workreport/`。
确保结构为：`/opt/workreport/src/backend/main.py` 存在。

### 2. 创建运行用户
```bash
sudo useradd -r -m -s /bin/bash workreport
```

### 3. 安装 Python 依赖
```bash
cd /opt/workreport
python3 -m venv venv
/opt/workreport/venv/bin/pip install -r src/backend/requirements.txt
```

### 4. 配置 API Key
确认 `src/backend/config.py` 里的 AI 配置正确：
- `DEEPSEEK_API_KEY`：公司网关的 API Key
- `DEEPSEEK_BASE_URL`：`https://atk.llschain.com/v1`
- 确认服务器能访问公司网关（防火墙放行，或走内网）

### 5. 配置 systemd 服务
```bash
sudo cp deploy/workreport.service /etc/systemd/system/
# 按实际路径修改 service 文件里的 WorkingDirectory、ExecStart、User
sudo systemctl daemon-reload
sudo systemctl enable workreport
sudo systemctl start workreport
# 查看状态
sudo systemctl status workreport
```

### 6. 配置 SSL 证书（HTTPS）
为域名 `workreporthr.hrlyit.com` 申请 SSL 证书（可用公司已有证书，或免费 Let's Encrypt），
把证书和私钥放到服务器，例如 `/etc/nginx/ssl/`：
```bash
sudo mkdir -p /etc/nginx/ssl
# 把证书文件放进来（文件名要和 nginx.conf 里一致）：
#   /etc/nginx/ssl/workreporthr.hrlyit.com.pem   （证书，含证书链）
#   /etc/nginx/ssl/workreporthr.hrlyit.com.key   （私钥）
```

### 7. 配置 Nginx
```bash
sudo cp deploy/nginx.conf /etc/nginx/conf.d/workreport.conf
sudo nginx -t          # 检查配置
sudo systemctl reload nginx
```
> nginx.conf 里已配置：80 端口自动跳转 https，443 走 SSL。域名、证书路径按实际调整。

### 8. 验证
- 浏览器访问正式域名：`https://workreporthr.hrlyit.com/`（应显示小锁图标）
- 健康检查：`curl http://127.0.0.1:8899/api/health` 应返回 `{"status":"ok"}`

## 四、数据备份

使用 `deploy/backup.py`，每天凌晨自动备份数据库，保留 180 天。

配置 cron：
```bash
crontab -e
# 添加以下行（每天凌晨 2 点备份）
0 2 * * * /usr/bin/python3 /opt/workreport/src/backend/backup.py >> /opt/workreport/backups/backup.log 2>&1
```

> 注意：backup.py 里的 `DB_PATH` 和 `BACKUP_DIR` 要按实际路径改。
> 建议同时把 `src/uploads/` 附件目录也纳入服务器级备份。

## 五、上线前必做

1. **修改默认密码**：所有账号初始密码是 `123456`，上线后必须让成员登录后自行修改（系统里已有"修改密码"功能）。
2. **确认数据库干净**：上线前确认 `workreport.db` 里没有测试数据。
3. **防火墙**：仅对外开放 80/443，8899 端口只对内网。

## 六、常见问题

- **AI 调用失败**：检查服务器到 `atk.llschain.com` 的网络连通性，以及 config.py 的 API Key 是否有效。
- **附件上传失败**：确认 `src/uploads/` 目录存在且 workreport 用户有写权限：`sudo chown -R workreport:workreport /opt/workreport/src/uploads`。
- **数据库写失败**：确认 `src/` 目录 workreport 用户有写权限。
